# **Cálculo de Oportunidades**
Las oportunidades son cálculos que se realizan de forma interna con el fin de mostrar con facilidad los clientes que son más liquidables.

En la **calculadora individual**, las etiquetas que se consideran con un descuento correcto son: **CAMBIO DE PAB, ACUERDO, DEPOSITO y ACTUALIZADO_ALIANZAS (Masivas)**. Cualquier otra etiqueta se toma como descuento 0%. En la **calculadora masiva** el descuento sale de la Base del Mes de Masivas cuando el toggle **Solo de Masivas de Alianzas** está activo, y de las Actualizaciones cuando está inactivo; nunca usa PaB simulado. Las oportunidades se calculan por **portafolio/unidad de análisis** y luego se consolidan por cliente.

Para tener en cuenta los portafolios: con Masivas se usa `Metadata.Id_Portafolio` (si está vacío, la deuda es individual); con Actualizaciones se agrupan las actualizaciones confiables consecutivas con la misma etiqueta y a ≤45 s (ventana configurable con `VENTANA_PORTAFOLIO_SEGUNDOS`). Si el cliente no tiene actualizaciones, se agrupan las deudas por cada banco de **Banco de Occidente, Banco Popular, Itaú y BBVA Colombia**; las demás deudas quedan individuales. El pago de un portafolio se usa una sola vez cuando las actualizaciones tienen el mismo valor o cuando Masivas trae `PaB_Portafolio`; si los valores difieren, se suman. Para Crédito, una unidad solo entra si **todas** sus deudas tienen PaB Ideal. Si el cliente no tiene registro en el Pipeline de Crédito se asume viable; solo se bloquea cuando el Pipeline reporta un estado no apto (no opta o rechazó Crédito).

Para esto se cuenta con las siguientes oportunidades que establecen diferentes formas de dar a entender que una o más deudas son liquidables:
> **Depósito Extra**: En caso que un cliente requiera *3 Apartados Netos o menos, o 1M COP o menos* se considera como una oportunidad para pedir depósito extra. Si `Apartado_Neto` es 0, solo aplica la condición de 1M COP.

> **ContraOferta Viable**: Teniendo en cuenta el ahorro del cliente o el pab ideal de credito se calcula el *descuento necesario para pagar la(s) deuda(s)*. Esta oportunidad tiene su propio apartado para ver como ajustar los descuentos y el ingreso que se puede generar. **NO APLICAN CLIENTES YA LIQUIDABLES**. Para varias deudas, el `Descuento Esperado` se pondera por `PaB_Origen`.

> **Acuerdos para Robo**: Acuerdos Vencidos que no cuenten con una gestión posterior con el cliente. La unión con Alianzas/Metabase es por deuda (`Id_Deuda`).

> **Liquidación Instantánea**: Clientes que con el Descuento Actual pasen el PAB Ideal de Crédito o cuenten con el dinero suficiente para pagar la/las deudas. En **Tradicional** se exige además un descuento actual mínimo del **3%**: tener el ahorro no basta si la deuda no tiene descuento. En Crédito no aplica ese mínimo.

> **IA Liquidadora**: El Modelo interno de IA para la liquidación de clientes (1 de cada 3 se paga) prioriza los clientes que se tengan en cartera

> **Estado de implementación:** la Calculadora Individual por Referencia ya implementa estas oportunidades y permite simular Ahorro, Por Cobrar, Depósito Extra y el PaB de cada deuda. El Depósito Extra simulado hace parte del ahorro disponible y reduce el depósito requerido en Tradicional y Crédito. El PaB simulado reemplaza el `PaB_Actualizado` en Depósito Extra, Descuento Actual (Liquidación Instantánea) y la comparación de la ContraOferta. También existe un input de **Portafolio Total** que distribuye automáticamente el monto por `PaB_Origen`, y un popover por deuda con los **Descuentos en Base** de alianzas para comparar y copiar al input de PaB.
